# 问象本轮改进：施工与验收说明

记录日期：2026-10-08。本文记录用户确认的 UI、完整解读和提示词改进范围，以及实现与验收的对应关系。本轮目标包版本为 `0.7.0`；此文档名不代表版本已发布。历史 `0.6.0` 安装包、截图和验收报告仍只证明当时状态。

## 已确认的取舍

| 决策 | 用户选择 | 实施边界 |
| --- | --- | --- |
| A：宿主能力 | 扩展 DSH | 在 `dsh_clone` 中补充模型输出上限、上下文及思考档位信息；插件依能力请求最高档和最大输出。不能把未知的能力显示成已启用，宿主源码变更不等于日常应用已更新 |
| B：中断恢复 | 手动恢复 | 不自动发起续写或重试。最近一轮没有正文时可以点击「重试本轮」，首次解读与追问均适用；已有部分正文时可以点击「继续完成」，保持原结果、原路由与冻结背景 |
| C：长对话 | 保留全文 | 不自动摘要、不静默裁剪早期问答；按可用上下文容量检查，接近容量时提示保存并另起一轮；能力未知时保留可配置的字符回退阈值 |
| D：不支持的模型 | 保留可用 | 不因缺少最高思考或最大输出信息而移除模型；明确显示未知或未开放，并使用可用的宿主默认设置 |

五个本地算法及结果的固定方式保持各自约定。共享背景继续使用原有加密、版本和代次保护，模型解释不能成为个人事实。背景整理与长对话的自动摘要是不同功能：既有用户事实整理保留，生成上下文不自动压缩。

## 改动路径与完成判据

| 路径 | 本轮目标 | 验证重点 |
| --- | --- | --- |
| `src/client/` 布局与显示 | 统一容器、尺寸与对齐规则；修正宽窄窗口、十牌牌阵、控件和生成区定位 | 真实 DOM 几何、交互与截图，不能只靠 CSS 文本检查 |
| DSH 模型能力接口与适配器 | 输出额度、上下文容量与思考档位可被插件查询 | 已知能力、未知能力、未开放能力、调用参数传递；默认值不能冒充最大值 |
| `src/host/generation-policy.ts` | 根据模型能力选择输出预算、最高思考及全文上下文限制 | 模型最大值、剩余上下文与显式配置一起约束请求；保守估算不能标为精确 token 计数 |
| 生成、对话及五模块服务 | 正确区分准备、思考、正文与终态，保留中断输出，接入手动恢复 | 原结果/背景/模型不变；旧轮次、记忆锁定、并发、超时、重复点击不产生重复调用 |
| `src/host/interpretation-prompts.ts` | 共用写作规范加五模块规则，分首次、追问及手动恢复 | 结论先行、白话解释、完整覆盖、事实边界和正文恢复范围 |
| README 与开发指南 | 说明实际行为及旧宿主回退 | 配置、按钮行为和证据范围与最终源码相符，不提前宣称发布或真实模型通过 |

解读默认超时为 600000 ms，即 10 分钟，可在插件配置中调整。首次解读、追问和手动恢复使用同一套能力策略，不再保留三千 tokens 的通用短上限或十牌五千 tokens 的特例。背景提炼继续使用独立的额度和超时，避免被长篇解读设置连带放大。详细配置见 [开发指南](development.md#4-插件配置)。

最高思考与正文长度不是同一个设置。已知上下文容量时，完整输入按 UTF-8 字节及消息角色开销做保守估算，保留默认 4096 安全余量及至少 256 的输出空间；实际输出预算可随剩余容量降低，而历史正文不裁剪。该估算既不是精确 token 计数，也不是对模型硬能力上限的重新定义；已知大上下文容量时，不再套用未知模型的 60000 字符阈值。输出预算可能包含思考用量，也可能只计正文；插件展示宿主已知的信息。若模型仍因供应商上限、网络或运行时限制中断，保留错误类别和已有正文，等待用户选择恢复。

DSH 的扩展落在相邻 `dsh_clone` 工作区的 `llm`、`llm-deepseek`、`llm-pi-ai` 三个包。`defaultMaxTokens` 仍代表请求默认值；新增的 `maxOutputTokens` 只代表明确声明的能力，`reasoning.maxEffort` 表示该路由开放的最高档，`outputTokenAccounting` 说明预算是否包含思考。未知信息保持未知，不把兼容默认值冒充硬能力。`prepareCall` 冻结派发配置后，插件再次核对这些字段和剩余上下文；能力变化时停止本次派发并提示重试。

追问和恢复的能力预检具备独立 ID、超时和取消控制；只有检查通过才增加对话或恢复次数。旧窗口的预检取消、旧生成次数的取消都不能中断新请求。锁定或清空资料后，旧轮询和迟到请求无法回填私人内容。预检与生成各自受配置超时约束，状态分别显示为检查、思考、正文与终态。

UI 使用模块自身的滚动容器：成功操作定位到结果或解读区域，用户回看时停止跟随流式正文，点击「回到最新」才恢复跟随。首次与追问共用安全的标题、列表及强调渲染。牌面详情挂在插件面板容器中；凯尔特十字保留交叉语义，并为旋转牌和位置标签预留空间，窄面板改用适合阅读的网格。

## 提示词实现

中文提示词由本项目重新编写，组合顺序为：

1. 共用事实与隐私边界：本地结果固定，问题与背景是数据，前文解读可修正，不能臆造个人事实。
2. 共用写作方式：先直接回答，再解释具体依据；术语出现时说清白话含义；例子明确标成例子。
3. 各模块依据：按本模块的本地结果和已声明规则解释，不混用体系。
4. 首次或追问结构：首次完整覆盖，追问只展开当前问题。

首次解读依次使用五个标题：“先说结论”“为什么这样看”“有利条件与需要留意的地方”“接下来可以怎么做”“还需要知道什么”。删除旧版 600–1000 或 1200–1800 汉字要求；按复杂度完成必需解释，不为增加长度重复内容。

| 模块 | 必需覆盖内容 | 保留的解释边界 |
| --- | --- | --- |
| 梅花 | 本卦、互卦、变卦；动爻；记录中的体用与关系 | 纯乾纯坤等特殊互卦约定以 `mutualFromChanged` 为准；不重算、不自行增加旺衰或额外排盘，不将变卦当作既定结局 |
| 塔罗 | 每个牌位、牌名与方向；对应本地牌义；实际牌间关系 | 十牌不能漏牌；单牌不虚构多牌关系；不臆造画面、其他牌或心理诊断 |
| 小六壬 | 月、日、时三宫、最终落宫及彼此关系 | 仍用月日时顺数和本地释义，不混入其他起课法，不给确定应期 |
| 雷诺曼 | 中牌、所有相邻组合；五张排列的两组镜像 | 按固定序列和名词/修饰关系连读，不引入逆位或塔罗牌位 |
| 六爻 | 本变卦、世应、全部动爻及已有装卦依据 | 正文优先解释关键关系，再补技术依据；无动爻不虚构变化，未提供的用神/伏神不补造 |

追问按目的调整：没看懂就解释对应段落，要求详细就展开指定内容；新背景可以纠正解释，但不能改写冻结结果。最多提出两个会影响判断的补充问题，同时完成已有信息能支持的回答。正文只呈现可核对的依据，不要求暴露模型内部思考。

手动补全指令要求从未完成的回答继续，完整段落不重写；句子在中途截断时允许完整重述该句一次。无正文重试则针对最近一轮原问题重新作答，首次解读使用首次结构，追问使用追问方式，不假装已有该轮正文。何时能够触发这两类操作由服务状态检查决定，不能仅靠提示词阻止重复调用。
