# G9-B：占星候选的独立需求与实施计划

核对日期：2026-10-07。状态：**评估与需求完成，星历与命盘模块尚未实施**。候选目标是西方热带黄道本命盘；没有计算真实用户命盘或购买星历许可。

## 第一阶段的产品与规则

建议首版显示太阳、月亮和八颗行星的黄经、星座度数、逆行状态，以及主要相位。出生时间和地点可靠时才计算上升、天顶与宫位；不详时明确提供不含宫位的行星位置结果。月亮在所知时间范围内跨星座时显示范围，不能把正午盘当作已知出生盘。行运、次限、合盘、小行星、恒星、恒星黄道与择时暂留后续。

计算规则需冻结为：地心、热带黄道、明确的视位置标志与历元；宫制首版建议整宫制，等宫与 Placidus 分别为后续规则版本。主要相位建议合／六合／刑／拱／冲，角度为 0°／60°／90°／120°／180°，统一容许度先固定 6°。这一容许度属于本产品选择，不声称占星界唯一标准。行星黄经、上升、宫位和相位均由本地内核生成，模型只解释冻结结果。

## 输入与共享背景

本次结构化输入需要公历年月日、出生时分与精度、出生地经纬度、IANA 时区、夏令时歧义选择和规则版本。经度与时区是不同字段，不能从城市字符串自行推断历史偏移。默认支持 1900—2100 年；精度不足就降级可计算的范围。农历出生日期需用户明确转换并确认公历结果，不能让模型读取背景文档后暗中转换。

0.4 文档仍是原文背景，不承担排盘参数数据库。生日、时间和出生地仅在用户确认后参与本次本地计算，保存时进入现有加密存储。供应商一般只需要命盘结果与用户选用的背景，不必发送精确经纬度；是否在问题中主动披露由用户决定。锁定、清空、他人模式、冻结背景与晚到任务失效复用公共框架。

IANA 已发布 2026e；这不能证明当前宿主已经更新。实施需记录实际 tzdb 版本，测试重复和不存在的当地时间，并让用户选择偏移或修正输入。[IANA 官方数据库](https://www.iana.org/time-zones)

## 依赖路线及许可影响

| 路线 | 已核对事实 | 适用范围与代价 |
|---|---|---|
| Astronomy Engine | npm `astronomy-engine` 2.1.19，MIT，没有运行时 dependencies；维护者提供 JavaScript 天体计算与坐标转换 | 适合无原生编译的行星位置原型；不能等同于完整占星排盘库，宫位和占星解释须自建、独立验证 |
| Swiss Ephemeris | 核心 C API 提供星历与宫位；AGPL 或 Professional 双许可 | 适合完整星历路线，但要先处理集成许可、数据文件、原生绑定或 WASM、各桌面平台打包 |

[Astronomy Engine 维护者仓库](https://github.com/cosinekitty/astronomy)、[npm 版本元数据](https://registry.npmjs.org/astronomy-engine/latest)、[MIT 许可](https://github.com/cosinekitty/astronomy/blob/master/LICENSE)

Swiss 的 `swe_calc_ut` 与 `swe_houses_ex` 接收 UT 儒略日；宫位接口经度向东为正、纬度向北为正，并有整宫等宫制代码。极区导致某宫制不能计算时须返回明确状态，不能静默切换宫制。绑定必须保留星历源和计算标志，防止数据缺失后自动退回另一星历而界面仍宣称相同精度。[Swiss 程序员文档](https://www.astro.com/swisseph/swephprg.htm)

Swiss 官方当前价格页为免费版 **0 CHF**、Professional unlimited **700 CHF**，核对日为 2026-10-07；这是许可价格，不含开发费用或税费。旧 PDF 文档出现的另一价格不能覆盖当前报价。AGPL 路线对整体集成和网络使用有义务，选择它之前应结合本项目发行方式审查；不能因为核心可下载就按本仓库 MIT 任意再发布。[官方价格页](https://www.astro.com/swisseph/swephprice_e.htm)、[官方许可说明](https://www.astro.com/swisseph/swephinfo_e.htm)、[Professional 合同](https://www.astro.com/swisseph/secont_e_2609.pdf)

建议后续 Goal 先用 Astronomy Engine 做可丢弃的本地精度对照实验，再以数据与许可审查决定正式路线；本轮未选择或引入任何绑定。天体计算本身不用付费 API，AI 解读依旧单独计费。工程粗估：行星＋整宫首版 12—18 个工作日；Swiss 多平台绑定与专业许可路线另加 5—10 个工作日，具体依打包平台和验证结果调整。

## 可复现的规则样例与边界

以下是人工数学样例，用于测试规则函数；**不是已计算的真实出生天体位置**。

| 输入 | 期望 | 用途 |
|---|---|---|
| 黄经 123.4° | 狮子座 3.4° | `floor(longitude/30)` 与余角 |
| 黄经 359° 与 1° | 最小角距 2°，在 6° 合相范围内 | 跨 0° 的圆周距离 |
| 黄经 10° 与 190° | 角距 180°，冲相 | 对冲与容许度端点 |
| 上升黄经 123.4°，整宫制 | 第 1 宫从狮子座 0° 开始，第 2 宫从处女座 0° 开始 | 宫头与上升点区分 |
| 时间不详、仅知道日期 | 不显示精确上升与宫位；月亮显示当日范围 | 输入精度不能被界面隐瞒 |

正式星历例盘须固定 UT、经纬度、黄道、视位置、星历文件与版本；同一条件对照维护者测试和 JPL/NOVAS 等独立天文来源，不能把不同标志下的差异归为程序错误。初次对照不少于 20 个日期，包含闰日、时区跨日、逆行转折、极区和月亮快速变化。Astronomy Engine 的天文精度声明仅用于候选评估，项目最终误差容限必须由实际对照记录决定。[维护者的设计与验证说明](https://github.com/cosinekitty/astronomy)

## 后续专项 Goal

| 阶段 | 工作 | 进入下一阶段的标准 |
|---|---|---|
| B0 规则与许可冻结 | 确定星历路线、使用方式、黄道与宫制、出生输入与精度策略 | 许可适配结论与完整版本／数据清单保存 |

| B4 打包与隔离验收 | 各目标平台依赖、离线星历可用性、隐私检查 | 运行证据与真实模型质量分开记录 |
