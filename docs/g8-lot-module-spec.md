## 产品流程

1. 门户显示“抽签 · 关帝100签”，入口说明固定底本名称；沿用 G4 的导航、模型选择和会话恢复。
2. 用户填写所问之事，选择“本次使用背景”“替他人问”。不要求真实姓名或生日；抽签本地规则无需这些输入。
3. 点击“摇签”。动画只是展示，随机数由Host生成；一次请求冻结一个签号，重连与重复提交返回同一结果。结果未经显示前也不因刷新再次抽取。
4. 展示“第N签”、四句原诗、原刻等级、原创释义和出处。等级标注为传统文本，不转成现实成功概率；“原文与异文”可展开查看校勘说明。
5. 可本地复制结果，或选择AI解读。首次AI解读等待共享背景更新并冻结背景版本；传入本次问题、固定签诗、原创释义、底本ID/版本和规则说明，模型解释不得覆盖签号或原诗。
6. 追问沿用首次AI的背景快照与本轮结果。结束、切换、另起一轮按现有记忆检查点提炼新增用户消息；签诗、等级和助手推测不作为个人事实写入背景。

首版只提供一次抽取，不增加“反复抽到满意签”的自动机制、不模拟掷筊确认，也不暗示代表某寺庙的宗教仪式。若将来加入掷筊，须作为独立规则版本定义概率、次数与终态；用户手动另起一轮始终可以保留前次结果的版本关联。

## 技术契约与并发

公共包只导出静态100签及 `drawLot` / `validateLotResult`；不依赖LLM，也不含用户内容。随机抽取使用 `crypto.randomInt(1, 101)`，不可用 `%100`截断字节而引入模偏差。测试通过注入固定随机返回值检查1与100边界；生成器运行在Host并拒绝越界值。

未来 `/api/lot/catalog` 返回库ID、内容版本和非私人卡片元信息；`/api/lot/create` 返回 `LotReading`：

```ts
type LotReading = {
  id: string;
  method: 'lot';
  libraryId: 'guandi-qing-collated-100';
  contentVersion: '1.0.0';
  number: number; // 1..100
  result: { title: string; poemLines: [string,string,string,string]; traditionalGrade: string };
  createdAt: string;
  memory: { useBackground: boolean; forOthers: boolean; frozenVersion?: number };
};
```

`create`、首解、追问、取消、结束携带当前私人会话 `epoch`；首解与追问复用 G4 公共解读生命周期、流式状态、取消和稳定错误码。各请求使用随机ID及幂等键；重复 `create`不重抽，结果ID冻结内容版本。Host恢复时按ID回读，不从客户端传来的签号直接生成解读。清空后旧epoch全部失效；锁定保留可重新本地抽签的能力，并清除私人问题/解读缓存。持久化的问题、AI输出、追问、背景快照都进入MemoryService私有加密记录，普通Session只有元信息。

内容编译时把 `lots.json` 编入包；扫描PDF、转录快照和对照图是开发证据，**不作为运行依赖一起载入**。模块不能联网抓取现代签解补内容。包完整性检查要覆盖内容版本与100签哈希，字体由宿主系统提供；视觉图形由项目原创实现。

## 独立实施次序与验收

| 阶段 | 工作 | 完成标准 |
|---|---|---|
| L1 | 接入静态内容与本地抽签核心 | 原文、等级、释义和来源不可变；1—100均可读，均匀抽取不越界 |
| L2 | Host创建与恢复、幂等、取消 | 重试不重抽；结果不能被旧页面改号；重连恢复相同签 |
| L3 | 门户与结果页面 | 原诗逐句显示；异文和来源可看；350px窄窗、深浅主题、键盘选择与复制可用 |
| L4 | 公共首解/追问/共享背景 | 背景首次冻结，追问不悄悄换版；替他人、单次停用与清空联动通过 |
| L5 | 回归与隔离桌面 | 类型/构建/测试、包回读、模拟供应商全流程、三树私人明文扫描；真实模型质量单列 |

必须加入首尾签、34项异文保持、98补字说明、重复提交、取消后重试、后台背景失败、旧epoch拒绝、锁定本地抽签、解读快照、复制十行以上结果和两模块现有回归。不得以固定样本抽签测试证明随机均匀；实现使用Node无偏 `randomInt`，统计冒烟只辅助诊断。完成本规格和内容包即达到原计划G8验收终点；真正抽签模块按上述L1—L5进入后续独立实施Goal。
