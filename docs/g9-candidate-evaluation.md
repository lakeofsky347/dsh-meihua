# G9：命盘与其他体系候选评估

核对日期：2026-10-07。交付范围为四个候选的独立需求、来源、规则样例、依赖许可、成本与施工阶段；**没有实施八字、占星、奇门或卢恩运行模块**。本轮不调用真实供应商、不安装新依赖、不购买许可。

## 推进次序与决定依据

八字优先进入独立专项 Goal：有可核对的维护者规则与测试，MIT 候选历法依赖可以本地计算，且与用户生日资料的需求直接相关。其首个验收门槛仍是结构化输入与换日／节气例盘，不能靠共享背景里的自然语言猜日期。

卢恩内容工程较轻，但古诗字母表与现代 24 符文不是同一套，需要先完成来源映射与原创中文。占星可先做星历精度实验，正式路线取决于宫位、时区与 Swiss 许可决策。奇门需要专门的规则决议与完整人工盘，适合在六爻专项的复核流程稳定后推进。后三者均是候选，当前没有将估算改成已启动的排期。

## 四个候选共用的输入与隐私合同

0.4 只维护一份背景原文文档，这一行为继续成立。未来需要日期计算的模块另设**本次计算输入**，只有用户明确确认的字段进入内核；不是由模型从记忆生成一个永久人物档案。原文里的农历／公历、闰月、出生时间不详、城市与时区不可擅自转换、补齐或重新解释。

本地内核输出和首次背景一起冻结，后续追问不能改盘。个人原始输入、解密缓存与保存结果进入现有 MemoryService 的清空／锁定／epoch 联动；默认无需另建生日明文数据库。供应商只获得解释需要的冻结结果与选用背景。关闭背景仍可以计算；替他人问禁止本人背景与本人记忆写入。日柱、星位或符文意象不是个人事实，不进入自动背景提炼。

日期模块必须记录规则版本、输入精度与实际时区数据库版本。IANA 最新 2026e 不等于当前 Electron/Node 已携带该版本；实施阶段检查运行环境。[IANA 官方时区数据库](https://www.iana.org/time-zones)

## 来源与验证范围

[g9-source-snapshots.json](g9-source-snapshots.json) 保存维护者 package、许可与八字测试原文快照（保留上游声明；不作为插件运行代码），包含当前 npm 版本元数据。后续启动 Goal 时再次核对时效性，再固定版本；本轮没有安装或执行候选库。八字表格为上游测试期望，奇门为古籍固定条件的人工地盘样例，占星为人工角度数学样例，卢恩为产品抽取合同样例。四者的证据层级分别标示，均不能冒充项目运行验收。

后续每个模块依次完成“规则／来源 → 本地纯计算或抽取 → 产品 → 公共记忆接入 → 打包与隔离验收”。至少分别记录本地算法、模拟供应商、真实供应商语义质量、许可和桌面运行结果；未开展的项目记 NOT_CHECKED。评估文件的完整性由 [g9-evaluation-manifest.json](g9-evaluation-manifest.json) 固定哈希，运行时不读取这些候选说明。
